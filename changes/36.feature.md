Fits can save their results to the database, through qililab's `DatabaseManager.add_fitting`: the fitted parameters go in the `fitting_parameters` column of the measurement entry and the path of the representative plot in `fitting_path`. No existing fit uses it yet; the node tickets add the calls. Two new `storage` keys control it:

- **save_to_database** : `bool`, optional, default `true`.
  Turns every fitting write on or off.

- **parameters_to_save** : `list[str]`, optional.
  Fitted parameters to save, out of the `FittedParameter` values. If it is not set, all of them are saved.

- `FittedParameter` is a `StrEnum` with the fitted parameter names agreed in QHC-1497 (`t1`, `t2`, `t2_echo`, `readout_fidelity`, `gate_fidelity_1q`, `gate_fidelity_2q`, `drive_if`, `drive_lo`, `readout_if`, `readout_lo`, `rabi_amplitude`, `drag_coefficient`, `cz_amplitude`, `flux_offset`, `sweet_spot_flux_offset_z`, `sweet_spot_flux_offset_x`, `thermal_population`, `fit_r2`, `fit_redchi`).
- `FittingClass.add_fitted_parameter(parameter, value)` collects a `FittedParameter`, rounded to 6 decimals. `save_fitting_to_database()` writes the collected parameters and `save_fitting_path_to_database(filepath)` writes the plot path. `save_plot(fig, title, save_to_db=True)` calls the latter once the plot is written to a file.
- The parameters and the path are written in separate calls, and neither overwrites the other, on both the `autocal` and `measurements` schemas. This needs qililab >= 0.36.0, where `DatabaseManager.add_fitting` no longer requires a path.
- Before `output_controller.reset()`, which a calibration run calls, `save_to_database` is unset: a `FittingClass` used on its own writes nothing. `output_controller.fitting_saving_enabled`, which both save methods check, raises a warning the first time that happens.

## **Example**
```yml
storage:
  root_dir: "/path/to/output/directory"
  db_manager:
    database_schema: "autocal"
  save_to_database: true
  parameters_to_save: ["t1", "readout_if", "fit_r2"]
```
