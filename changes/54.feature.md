The `reset_point_search` step runs as a `ResetPointSearchNode`, a port of the experimentalists' reset-point-search calibration script (QHC-1807). It moves the qubit line into the tree's `[target_freq_min, target_freq_max]` window by stepping the flux and re-measuring, then writes the reset point's absolute `flux.z` and drive IF (ADR-0011). The crosstalk matrix is left alone.

- Each measurement is the shared `two_tone_saturation` QProgram from `qili-qprograms` (QHC-1916), run through the new `TwoToneSaturationNode` spine. The spine sets the operating point's hardware with `_set_operating_point_hardware` and streams with `_stream`.
- The node runs at the step's `operating_point` (QHC-1936): it searches from that point's flux and writes that point.
- A rejected fit widens the span (the `drive_if_sweep` window, then 30 MHz, then 60 MHz). The flux steps are a probe, then a secant clipped to the maximum step, with `flux_settle_duration` (ns) after each move. The step fails after the move limit.
- `LorentzianPeakModel` fits the two-tone line's rotated quadrature. It accepts a fit only if R² ≥ the step's `min_r2`, the centre is inside the sweep, and the sweep step < linewidth < span. It saves `drive_if` and `fit_r2` to the measurement entry.
- One Lorentzian fit (QHC-1932 item 5): `FittingClass.fit_lorentzian` is a bounded local least-squares fit started from `FittingClass.lorentzian_initial_guess`, which reads the baseline, centre, height and width off the trace. `LorentzianPeakModel`, `two_tone_vs_flux` (through `lorentzian_fit`) and the legacy two-tone fit all use it. It replaces `lorentzian_fit`'s `differential_evolution` fit, which reported the grid point at the fitted extremum, and the script's start, whose width came from the stored IF and was zero for an IF of 0. The fit is deterministic, so `two_tone_vs_flux` no longer refits a poor trace up to 20 times.
