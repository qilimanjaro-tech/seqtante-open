The calibration graph is built from the parsed tree and run with real dependencies (QHC-1800).

- `CalibrationRun` builds the graph from the selected pipelines before connecting to the platform: one node per step, with edges from the order of steps within a pipeline and from each pipeline's `after`. Each step runs as its registered `CalibrationNode` (with the run context) once its experiment is ported, and through the legacy-function adapter until then (ADR-0007).
- `--calibration` is the run's calibration file: a serialized `Calibration` (ADR-0001), deserialised once into the context the nodes share and used to satisfy an unselected dependency.
- Pipeline selection: `--pipelines` runs only the named pipelines, and a pipeline with `enabled: false` never runs. Selecting an unknown or disabled pipeline, or a selection that runs nothing, is an error.
- Failure handling is per target: a target that fails a step skips the rest of that target's pipeline and, transitively, any pipeline whose `after` names the failed step; other targets and other pipelines keep running. A run report records, per target, where and why it stopped.
- A dependency on a step that is not run this time is satisfied from the calibration file, for every step's targets (ADR-0003): a target the file does not have the dependency step's operating point or section for fails that step, and stays blocked in the rest of its pipeline, with a report entry.
- `after` cycles between pipelines are rejected with a clear error at build time, before the platform connects. From `connect` onward the run is closed out in a `finally` that zeroes the bias, ends the run entry and disconnects, so a failure never leaves the instruments on.
- Pipeline-level keys are validated: an unknown pipeline key (such as a misspelt `enabled`), and `enabled`/`after`/`steps` written on a step, are errors.
- `CalibrationNode` accepts `QubitTarget`/`CouplerTarget` targets (ADR-0001), which were previously skipped as an invalid type.
