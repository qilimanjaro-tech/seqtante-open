The calibration graph is built from the parsed tree and run with real dependencies (QHC-1800).

- `CalibrationRun` builds the graph from the selected pipelines before connecting to the platform: one node per step, with edges from the order of steps within a pipeline and from each pipeline's `after`.
- Pipeline selection: `--pipelines` runs only the named pipelines, and a pipeline with `enabled: false` never runs. Selecting an unknown or disabled pipeline is an error.
- Failure handling is per target: a target that fails a step skips the rest of that target's pipeline and, transitively, any pipeline whose `after` names the failed step; other targets and other pipelines keep running. A run report records, per target, where and why it stopped.
- A dependency on a step that is not run this time is satisfied from the calibration file: the existing file is loaded at the start of the run, and a target with no entry fails the dependent step with a report entry.
- `after` cycles between pipelines are rejected with a clear error at build time, before the platform connects.
- Pipeline-level keys are validated: an unknown pipeline key (such as a misspelt `enabled`), and `enabled`/`after`/`steps` written on a step, are errors.
- `CalibrationNode` accepts `QubitTarget`/`CouplerTarget` targets (ADR-0001), which were previously skipped as an invalid type.
