Fixed `FluxoniumSingleToneModel`, which could not complete a run:

- `fit()` records its answer in `results`, where the `single_tone` node reads it from
  (`results["signal"]["fitted_if"]`). `results` existed only as an annotation and was never
  assigned, so the node raised `AttributeError` after every measurement.
- `plot()` builds a `plotly` figure and hands it to `FittingClass.save_plot(fig, title)`. It was
  still matplotlib and passed the title in the figure slot, so it wrote no image, and the figure
  it left open leaked into whatever ran next in the same process.
- `lo` can be omitted again: it falls back to the readout bus LO in the runcard stored with the
  measurement, the way the flux-swept sibling already did. Left unset it raised
  `TypeError: unsupported operand type(s) for +: 'int' and 'NoneType'`.

`__init__` now reaches the trace through `get_xarray()` and exposes `readout_bus`, matching the
other fits. The resonance is still the deepest point of the magnitude trace: only where it is
stored, and how it is drawn, have changed.
