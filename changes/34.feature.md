Added the three-phase node lifecycle, benchmark verdicts and the two mid-level spines (ADR-0006, ADR-0002, ADR-0004). The final slice of the node base (task 5): every experiment now subclasses `CalibrationNode` and implements three phases that `run` drives.

- **`CalibrationNode.run`** places the live targets at their operating point (when `applies_operating_point`), then calls `execute_node`, `analyze` and `apply` in order, all wrapped in the crosstalk session and the restore context manager. It returns the targets whose `analyze` raised an analysis error, so the graph skips their later steps; a target already stopped by an earlier node is left out.
- **`execute_node` / `analyze` / `apply`** are the three abstract phases (ADR-0006). `execute_node` measures and returns the measurement ids per target; `analyze` is read-only and returns an `AnalysisResult`, raising `AnalysisError` when the fit does not converge or falls below the tree's threshold; `apply` is the only writer and runs only for targets whose `analyze` succeeded. A node carries its fitted payload from `analyze` to `apply` in `AnalysisResult.fitted`, whose type each node fixes.
- **Verdicts** (`verdicts.py`): `Verdict` (Passed/Warning/Failed), `BenchmarkDirection`, `BenchmarkThresholds`, `BenchmarkResult` and `verdict_for`, which scores a benchmark's value against the tree's thresholds in the node's direction. A `Failed` verdict is a result, not a step failure (ADR-0002, D17); `run` collects benchmark results on the node for the report, and a benchmark writes nothing back.
- **`FixedFluxNode` and `FluxSweepNode`** are the two mid-level spines the experiment nodes subclass (ADR-0004); they set no `experiment` and are not registered. They fix whether the node is pinned to one operating point, and hold the code the two experiment shapes share as the nodes are ported (tasks 6–12).
