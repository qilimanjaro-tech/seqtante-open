The `two_tone` step runs as a `TwoToneNode` (`FixedFluxNode`) at the sweet spot (QHC-1805).

- One two-tone pulsed-saturation sweep at the step's operating point, fit to a Lorentzian peak. The QProgram is `two_tone_saturation` from `qili-qprograms` (QHC-1916), which takes the `readout-<op>` pulse, its weights and the readout IF from the calibration file; the node runs it through the `TwoToneSaturationNode` spine it shares with `reset_point_search` (QHC-1807), which sets the drive/readout LOs, readout attenuation and drive source through the base node's shared `_set_operating_point_hardware` (`drive_power` for a Rohde & Schwarz source, `drive_gain` for a QCM-RF). Step parameters are named like the qili arguments (`drive_ringup_time`, `drive_ringdown_time`, `drive_n_sigmas`, `readout_ringup_time`) and default through the node's `defaults`; the drive window is `drive_if_sweep`, `np.linspace` arguments as offsets from the stored drive IF (QHC-1932), and `readout_amplitude`/`readout_duration` are no longer step parameters. The example tree's `two_tone` defaults follow. `apply` writes the fitted drive IF onto the sweet-spot operating point and leaves the LO (placed outside the sweep) untouched. The legacy `save_platform` write is gone: the run persists the calibration file (ADR-0001).
- The fitted `drive_if`, `drive_lo` and `fit_r2` are written to the measurement entry (QHC-1497, QHC-1791).
- `two_tone` now carries a `node_cls` in `NODE_REGISTRY` and is dropped from the legacy `experiment_functions_dict`. The Lorentzian fit is shared with `reset_point_search` (QHC-1807).
- `LorentzianPeakModel`'s plot-title prefix is configurable, so each caller labels its own sweep.
- A Rohde & Schwarz drive source now has its IQ modulation switched on before the sweep (in the shared two-tone measurement and the legacy `two_tone_frequency` / `two_tone__frequency_vs_flux` drivers), so it plays the IQ drive rather than a bare carrier.
- `reset_point_search` and `two_tone` measure through `CalibrationNode._stream` (QHC-1932), and fail the target before any hardware is set when the `readout-<op>` pulse is missing (`_require_pulse`). `reset_point_search` takes the same `drive_if_sweep` window, around the stored drive IF, re-centres it as the flux moves and widens it to `retry_spans` at the same spacing; its settle wait is `flux_settle_duration` in ns. The example tree's reset step sets `target_freq_min` / `target_freq_max`, the keys the node reads.
