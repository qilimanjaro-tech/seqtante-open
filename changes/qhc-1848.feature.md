Reconciled the benchmark thresholds and direction onto one representation and wired the parser's thresholds into the verdict scoring (QHC-1848, the core of the reconciliation agreed with Ely on PR #34).

- **One direction type.** `BenchmarkDirection` (the `verdicts.py` enum) is now the single direction type. `node_registry.Direction` (the `"higher"`/`"lower"` literal) is gone; `BenchmarkSpec.direction` and the parser use the enum.
- **One thresholds type.** The parser's `Thresholds` is gone; the parser now produces `verdicts.BenchmarkThresholds` (which gained the `unit` field), so there is a single thresholds type, living in `verdicts.py` where `verdict_for` consumes it and the import graph stays acyclic.
- **The run scores the benchmark.** A node's `analyze` now reports the measured `value` (and `uncertainty`) on `AnalysisResult`, not a pre-scored result; the base's `run` scores that value against the step's thresholds with `verdict_for` and builds the `BenchmarkResult`. Scoring lives in one place (the run), not in each node's `analyze`.

The analyses-to-fittings mapping, the benchmark-defines-its-benchmarks model note, and a `Verdict.error` with a plot on analysis failure (a benchmark with no thresholds is currently left unscored) are tracked as follow-ups on QHC-1848.
