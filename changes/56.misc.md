Added a dry run of a calibration tree, `uv run python -m scripts.dry_run`, and a local database for seqtante in `db_docker/`. No change to the package.

- The dry run runs the real `CalibrationRun` with no hardware. The platform is built from the runcard and never connected; every QDAC-II is the real qcodes driver on pyvisa-sim (`scripts/dry_run/qdac_sim.py`), which records the SCPI it receives and answers qililab's internal-trigger queries from the marker registers written so far. `execute_qprogram` compiles each QProgram as on hardware and starts the QDACs, then returns fake data on the sweep the node streams, in the shape the hardware returns it.
- The fake data is the fit tests' data builders, evaluated on the node's own sweep. Its features are set by environment variables `DRY_RUN_[<TARGET>_][<STEP or EXPERIMENT>_]<NAME>`, the most specific first: `FEATURE_AT`, `QUBIT_IF`, `RESONANCE_IF`, `SWEET_SPOT`, `SWEET_SPOT_IF`, `PI_AMPLITUDE`, `T1`, `T2` and `NOISE`. `FAIL=fit` gives featureless data the analysis rejects, and `FAIL=execution` raises after compiling, as a hardware error would. A key that names nothing in the tree, or a bad value, stops the run before it starts.
- Without `--calibration`, a calibration file is made up from the tree: its operating points for every target, a square readout and a DRAG π pulse each, and an identity crosstalk matrix. A file given is copied, since the run writes to it.
- Each run gets a folder under `data/dry_runs/`: the tree, calibration and database section it used, the seqtante outputs and `.h5` files, and, for every execution, the Q1ASM of every bus, the SCPI each QDAC received and the fake-data values.
- It writes to `db_docker`'s database by default, or to any `.ini` section given with `--database_ini` and `--database_section`. Only that section is used, with schema `autocal` when it declares none. The run connects through a copy in a temporary folder deleted at the end; the copy kept in the run folder has no `passwd`. Tables are created only in `db_docker`'s database. See `scripts/dry_run/README.md`.
- `db_docker/` is a Postgres 16 in Docker on port 5436 (`seqtante` / `seqtante`, local only), with a `database.ini` a tree's `storage.db_manager` can point at. `python -m db_docker.create_tables` creates the `autocal` or `measurements` tables, empty, from the installed qililab's own models, and leaves existing ones alone. See `db_docker/README.md`.
- The fit tests' data builders take keyword-only arguments for their sweep axes, the value that places the feature (`qubit_if`, `resonance_if`, `sweet_spot`, `sweet_spot_if`, `pi_amplitude`, `t1`, `t2`) and the noise `sigma`. Each defaults to its old constant, so the tests and the committed `.h5` files are unchanged. See `tests/experiments/fitting/README.md`.
- `pyvisa-sim` is in the `dev` dependency group. `uv.lock` is rewritten in format revision 5 by uv 0.13; no other locked version changes.
